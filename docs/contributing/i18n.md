# Translations (i18n)

The console speaks English (the source language), Russian (`ru`) and Uzbek (`uz`, Latin script). Strings
live in JSON files and are rendered with [i18next](https://www.i18next.com/) and
[react-i18next](https://react.i18next.com/). The server stays English; the console translates what it shows.

## Where things are

| Path | Contents |
|---|---|
| `web/src/locales/{en,ru,uz}/<namespace>.json` | the strings, one namespace per feature |
| `web/src/locales/resources.ts` | the English bundle and the namespace list |
| `web/src/locales/i18next.d.ts` | key typing from the English JSON |
| `web/src/lib/i18n.ts` | setup, language detection, `setLanguage`, `intlLocale` |
| `web/src/lib/format.ts` | bytes, counts, durations, relative times and dates in the current language |
| `web/src/lib/error-message.ts` | `errorMessage(err)`: API error code to translated text |
| `web/src/components/layout/language-select.tsx` | the picker on sign-in pages (the account menu has its own list) |
| `web/scripts/i18n-check.mjs` | compares every locale with English |
| `web/src/locales/CONVERTING.md` | step-by-step recipe for converting a feature folder |

English is bundled with the app. Russian and Uzbek load on demand: one small chunk per locale and namespace,
so the first-route bundle carries no translations.

## Namespaces

One namespace per folder in `web/src/components/features/`, named like the folder, plus shared ones:

| Namespace | Covers |
|---|---|
| `common` | shared words (Save, Cancel, Retry, Copy…), the UI kit, time and unit formats |
| `shell` | sidebar, top bar, ⌘K palette, breadcrumbs, account menu, theme toggle, home page |
| `auth` | sign-in, two-step verification, setup, password change, invite pages |
| `errors` | messages for API error codes |
| `apps` | the new-app page and project pages (`routes/$org.apps.new.tsx`, `$org.projects.$p.tsx`, `$org.apps.$app.tsx`) |
| `<feature>` | `admin`, `app-header`, `app-settings`, `audit`, `branding`, `domains`, `editor`, `empty`, `env`, `invites`, `logs`, `members`, `org`, `overview`, `secrets`, `security`, `tokens`, `triggers`, `versions` |

A change to one feature touches only its own three JSON files.

## Add a string

1. Add the key to `web/src/locales/en/<namespace>.json`. Group with nested objects
   (`"remove": { "title": "…" }`), use camelCase keys that say what the string is (`remove.confirm`, not
   `button2`).
2. Use it:

   ```tsx
   import { useTranslation } from "react-i18next";

   const { t } = useTranslation(["members", "common"]);
   t("remove.title", { name });   // members namespace
   t("common:cancel");             // another namespace needs the prefix and must be in the list
   ```

   Outside React (toasts in hooks, helpers) import `i18n` from `@/lib/i18n` and call
   `i18n.t("members:toast.removed", { name })`.
3. Add the Russian and Uzbek text to `ru/<namespace>.json` and `uz/<namespace>.json`.
4. Run `npm run i18n:check`.

Keys are typed from the English JSON: a key that does not exist fails `tsc`. Dynamic keys need a typed
union (see `ROLE_KEY` in `features/members/roles.ts`, or `OAUTH_ERRORS` in `routes/login.index.tsx`).

### Rules

- Never build a sentence from pieces (`"Removed " + name`). Use interpolation: `"Removed {{name}}."`.
  Word order differs between languages.
- Inline markup goes through `<Trans>` with named tags:
  `"typeToConfirm": "Type <mono>{{value}}</mono> to confirm"` and
  `<Trans i18nKey="typeToConfirm" values={{ value }} components={{ mono: <span className="font-mono" /> }} />`.
- Translate everything a person can see or hear: text, `aria-label`, `title`, `placeholder`, `alt`, toasts,
  confirm dialogs, empty states and validation messages.
- Do not translate: identifiers (slugs, emails, URLs, cron expressions), API field names, log lines, code,
  metric keys from the runtime (`labelFor` stays English).
- A different sentence per state uses i18next context: `t("toast.roleChanged", { context: role, name })`
  with keys `toast.roleChanged_owner`, `toast.roleChanged_admin`, `toast.roleChanged_member`.

## Plurals

Use `count` and the i18next plural suffixes. English needs `_one` and `_other`:

```json
"count_one": "{{count}} member",
"count_other": "{{count}} members"
```

Russian needs `_one`, `_few`, `_many` and `_other` (1 участник, 2 участника, 5 участников, 21 участник;
`_other` is for fractions). Uzbek needs `_one` and `_other`, usually the same text (`{{count}} ta aʼzo`:
Uzbek nouns do not change after a number). The check script knows which forms each language needs.

## Formatting

Use `web/src/lib/format.ts`, never `toLocaleString()` or hand-made units:

| Function | Example (en / ru / uz) |
|---|---|
| `formatBytes(1536)` | `1.50 KiB` / `1,50 КиБ` / `1,50 KiB` |
| `formatCount(100000)` | `100,000` / `100 000` / `100 000` |
| `formatDuration(2500)` | `2.5 s` / `2,5 с` / `2,5 s` |
| `formatRelative(ts)` | `5 min ago` / `5 мин назад` / `5 daq oldin` |
| `formatDateTime(ts)`, `formatDate(ts)` | Intl date in the current language |

For anything else, pass `intlLocale()` from `@/lib/i18n` to an `Intl` formatter.

## API errors

Show errors with `errorMessage(err)` from `@/lib/error-message`. In English it returns the server message
(it can be more specific); in Russian and Uzbek it returns `errors:<code>` when that key exists, and the server
message otherwise. The global mutation toast in `lib/query.ts` already does this. When a page handles a
code itself (for example `last_owner` on the members page), give that message a key in the page's namespace.
New server error codes get a key in `errors.json` in all three languages.

## Check the locale files

```sh
cd web
npm run i18n:check                    # strict: fails on missing keys
npm run i18n:check -- --allow-missing # what CI runs while features are being translated
```

It fails when a locale has a key English does not have, when a plural form the language needs is missing,
when `{{variables}}` or `<tags>` differ from English, or (strict mode) when a key is not translated. `make ci`
runs it with `--allow-missing`; drop the flag once every namespace is translated.

Tests run in English: `web/src/test/setup.ts` loads English synchronously and resets the language after each
test, so tests keep matching English text. To test another language, `await setLanguage("ru")` first.

## Translation guidelines

- Short, plain, polite UI language. Russian uses the formal «вы» (lowercase), Uzbek uses «siz».
- Buttons are verbs: «Сохранить», «Saqlash». Titles are nouns.
- Keep the English punctuation style: a period ends a full sentence, not a label or button.
- Russian: «ё» where it is standard (Тёмная), guillemets «…» for quoted names, a non-breaking space is not
  needed in JSON.
- Uzbek: Latin script only. Write oʻ and gʻ with U+02BB (ʻ), the tutuq belgisi with U+02BC (ʼ): `oʻ`, `gʻ`,
  `aʼzo`. Never the ASCII apostrophe or a backtick.
- Product and protocol names stay as they are: Runtime, GitHub, OAuth, SSO, TOTP, URL, DNS, TXT, cron.
