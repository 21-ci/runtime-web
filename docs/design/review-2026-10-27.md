# Runtime Web review: problems and fixes (2026-10-27)

Status: hand-off for an implementing agent. Not in the MkDocs nav.
Scope: branch `feat/installer`, including its uncommitted work (apps moving from `/s/<slug>/` to
`<slug>.<apps-domain>`). Every item was checked against the code, and `file:line` references are as of that date.

Before you start, read `AGENTS.md` and `docs/contributing/code-style.md` (binding). Use the `add-api-endpoint` skill for
API changes and the `ui-design` skill for `web/` changes. A change is done only when `make ci` passes. Each item lists
acceptance criteria. Add or adjust Vitest tests with `testApp()` and `FakeRtCtl` on the server, and with Testing
Library and MSW in the console.

Priorities: **P0** fix before release · **P1** next · **P2** hardening · **P3** product/roadmap.

## P0

### 1. Saving goes live, but the docs say it does not
- **Where:** `server/src/apps/service.ts:285-298` (`saveFiles` calls `setLive`); `web/src/components/features/editor/code-page.tsx:84-106`;
  docs `docs/user-guide/editor.md:13`, `docs/user-guide/apps.md:25`.
- **Problem:** Every save uploads, builds and promotes the version to live, so a bad save takes production down at
  once. The docs say "Saving does not deploy it."
- **Fix (pick one, A recommended):**
  - A. Split save and deploy. `saveFiles` uploads and builds only. A separate "Deploy" action calls the existing
    promote (`setLive`) endpoint. The editor shows "Saved vN (not live)" plus a Deploy button. The preview iframe gets
    a toggle between the live version and the latest saved version, if the runtime can address a version (check
    `runtime/types.ts`). If it cannot, keep the preview on live.
  - B. Keep save = deploy and fix the docs and UI copy. The button label becomes "Save & deploy".
- **Accept:** the code and docs agree. With A, a test proves that `PUT …/files` does not change `live`, and that
  promote does.

### 2. Project viewers can read env values in plaintext
- **Where:** `server/src/routes/apps.ts:118-121` (`GET …/env` gated by `app.read`); `server/src/authz/policy.ts:71`
  (`app.read: projViewer`).
- **Problem:** Env often holds third-party API keys. Secrets are write-only, but env is readable by the lowest role.
- **Fix:** Add an action `app.env.read` mapped to `projDeveloper` in `policy.ts` and use it on `GET …/env`. In the
  console, viewers see names with masked values, or the Env tab shows a "requires developer" notice. Update
  `docs/reference/api.md` and `docs/security-model.md`.
- **Accept:** a viewer gets 403/404 (match the existing convention for denied app actions) and a developer gets 200.
  Authz matrix test updated.

### 3. `tls-ask` makes one runtime call per org (uncommitted code)
- **Where:** `server/src/routes/internal.ts`, `isAppHost`.
- **Problem:** It loops over every org and calls `deps.apps.resolve` (a runtime call) for each one. A task is capped at
  about 50 outbound fetches, so past roughly 45 orgs the check fails and new apps never get a certificate. It is
  also slow on every first TLS hit.
- **Fix:** Resolve the slug with a single lookup:
  - Preferred: an operator call through `rtctl.op` that finds a service by slug node-wide, if the runtime has one
    (slugs are unique on the node). Check `server/sdk/rtctl/` and `runtime/types.ts`.
  - Otherwise: add a migration with an `apps(org_id, slug UNIQUE, service_id)` index table. Write to it in
    `createApp`, and delete from it in `deleteApp` in the same flow. Backfill it lazily or in `scheduled()`.
    `isAppHost` then becomes one `SELECT`.
- **Accept:** a test with 60 orgs answers `tls-ask` with at most 1 runtime call (assert on the `FakeRtCtl` call count).

### 4. Slugs are not validated in the console
- **Where:** `server/src/routes/apps.ts:43-56` (`POST` create accepts any non-empty string);
  `server/src/apps/templates.ts:67-69` (slug substituted into source).
- **Problem:** Slugs now become DNS labels (`<slug>.<apps-domain>`). The console relies entirely on the runtime to
  validate them. The design doc requires `[a-z0-9-]`, ≤ 63 characters, no leading or trailing `-`, and no `--`.
- **Fix:** Validate in the route with a shared regex such as `^(?!.*--)[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$`, return
  `invalid({ slug: "pattern" })`, and reuse the same constant in `internal.ts` (it has its own `SLUG` today). Mirror
  the rule in the new-app form.
- **Accept:** table test for valid and invalid slugs, and an api.md row update.

## P1

### 5. App create and delete are not atomic
- **Where:** `server/src/apps/service.ts:158-166` (create cleanup is `.catch`-logged only); `:238-243` (delete calls the
  runtime first, then `removeAppDomains`).
- **Problem:** A failed cleanup leaves an orphan service holding the slug. A failed domain removal leaves domain rows
  pointing at a deleted service, with no retry (only `pending_unmaps` is retried in `jobs.ts`).
- **Fix:** Reuse the retry-queue pattern (`pending_key_revokes` / `pending_unmaps`):
  - Add `pending_service_deletes(service_id, tenant_id, attempts, next_at)`. Enqueue the service when the create
    cleanup fails, and retry it in `scheduled()`.
  - In `deleteApp`, mark the domains for unmapping (or delete the rows and enqueue the unmaps) before or in the same
    batch as the runtime delete, so the step can be retried.
- **Accept:** tests inject failures into `FakeRtCtl` and show the scheduled job converging.

### 6. Env writes have no concurrency control
- **Where:** `server/src/routes/apps.ts:123-134` (full-map PUT, no If-Match);
  `web/src/components/features/env/env-editor.tsx:124,136,148`.
- **Problem:** Two editors, or two quick row edits, silently drop keys.
- **Fix:** Return an `ETag` (a hash of the env map) on `GET …/env` and require `If-Match` on `PUT`, answering 412 on
  mismatch, as `saveFiles` already does. Optionally add `PATCH …/env` with `{set:{}, unset:[]}` for row edits. The
  console sends the etag and, on 412, refetches and shows a conflict toast.
- **Accept:** a test where a stale PUT gets 412.

### 7. Unsaved code is lost on in-app navigation
- **Where:** `web/src/components/features/editor/code-page.tsx:126-130` (only `beforeunload`).
- **Fix:** Use TanStack Router `useBlocker` while the editor is dirty, with the existing `ConfirmDialog`.
- **Accept:** a test where a dirty editor plus a route change prompts the user.

### 8. Bearer tokens cannot call the console API; the docs say they can
- **Where:** `server/src/auth/middleware.ts` (session + CSRF only); `docs/user-guide/tokens.md:3`.
- **Problem:** Agents, CI and scripts cannot use `/api/*`. This is the main blocker for automation and AI agents.
- **Fix:**
  - Short term: correct `tokens.md` so tokens call the runtime control API only.
  - Proper fix: accept `Authorization: Bearer <token>` on `/api/orgs/:org/apps/*`. Hash-verify it against the
    `tokens` table, then map the token scopes (`deploy`, `env:write`, `secrets:write`, `invoke`, …) plus its
    `projects` and `envs` lists onto the policy actions. Bearer requests skip CSRF and Origin (no cookie involved)
    but must not carry a session cookie. Rate-limit them per token. Audit them with the token id as the actor.
    Never allow bearer tokens on the auth, users, tokens or admin routes.
- **Accept:** tests show a scoped token can deploy and read logs in its project, gets 403 outside it, and is rejected
  on the token-mint and admin routes.

### 9. Log streaming: polling per viewer and no reconnect
- **Where:** `server/src/apps/logs.ts:1-23`; `web/src/components/features/logs/use-log-stream.ts:94`; `web/src/components/features/logs/logs-view.tsx`.
- **Fix:**
  - Console: when the stream is `closed`, show a "Reconnect" button and auto-retry with backoff.
  - Server: keep the per-request poll (the runtime has no shared hub), but add backoff when no new lines arrive
    (1 s → 3 s) to cut runtime load with N viewers.
- **Accept:** a console test for the reconnect UI.

### 10. One concept, three env var names
- **Where:** `RTWEB_APPS_URL` (`docker-compose.yml:25`, `docker/entry/config.go:88`); `RTWEB_RUNTIME_PUBLIC_URL`
  (`server/src/config.ts`, `docker/entry/bootstrap.go`); `RTWEB_APPS_DOMAIN` (`deploy/Caddyfile`, `install.sh`, docs).
- **Fix:** Settle on one name for the origin (`RTWEB_APPS_URL`, `https://apps.example.com`) and derive the host from it
  where Caddy needs a bare host (or keep `RTWEB_APPS_DOMAIN` only as a derived Caddy env written by the installer).
  Accept the old names with a deprecation warning. Update `docs/reference/configuration.md`. Remember that
  `docker/entry` mirrors `install.mjs` and the Caddyfile, so change them together.
- **Accept:** grep shows one user-facing name, and Go tests plus `config.ts` tests pass.

### 11. Default to wildcard certificates for the apps domain
- **Where:** `deploy/Caddyfile` (per-app on-demand TLS), `install.sh --tls`.
- **Problem:** Let's Encrypt allows 50 certificates per registered domain per week, so one certificate per app hits
  the limit quickly.
- **Fix:** When a DNS provider token is given (the Cloudflare module is already planned in static-hosting r5), issue
  `*.<apps-domain>` via DNS-01 and keep on-demand TLS for custom domains only. Without a token, warn at install time
  about the limit.
- **Accept:** the installer generates a wildcard site block when the token is set, and docs are updated.

### 12. No timeout on runtime calls
- **Where:** `server/src/runtime/client.ts:68-83` (`Scoped.raw`).
- **Fix:** Wrap SDK calls in a timeout (for example 10 s, configurable) that maps to `504 runtime_timeout` through
  `runtime/errors.ts`.
- **Accept:** a test with a hanging fake shows the request fails with that code.

## P2: security hardening

### 13. Apps and console share a registrable domain (same-site)
- **Where:** `deploy/Caddyfile` (apps wildcard), `server/src/config.ts:40-52`.
- **Problem:** `apps.example.com` and `console.example.com` are same-site, so SameSite=Lax gives no protection against
  requests from App origins. It is safe today thanks to the `__Host-` cookie, the CSRF token and the Origin check, but
  one GET handler with side effects or one CORS rule would expose the console.
- **Fix:**
  - Add a `Sec-Fetch-Site` check in `originCheck`: reject unsafe methods unless the value is `same-origin` or `none`.
  - Assert in tests that no `GET` route mutates state.
  - In the docs, recommend a separate registrable domain for apps (as val.town uses val.run) or a PSL entry, and have
    `config.ts` warn when both hosts share an eTLD+1.

### 14. Fail closed when the apps origin is missing in production
- **Where:** `server/src/config.ts:40-45`.
- **Fix:** If `insecureCookies` is false and `RTWEB_RUNTIME_PUBLIC_URL` is empty, throw `ConfigError`.

### 15. OAuth SSRF guard checks the hostname as written only
- **Where:** `server/src/auth/oauth.ts:225-245,275,283`.
- **Fix:** Resolve the issuer, discovery and token hosts via DoH (reuse `domains/checker.ts`) and reject private,
  loopback and link-local addresses. Low impact, because only an admin can configure it.

### 16. Lockout can be used to deny service
- **Where:** `server/src/auth/ratelimit.ts:34-37,60-63`; `server/src/auth/totp.ts:71,75`.
- **Fix:** Key the account-wide delay on (email, /24 or /64 prefix) as well as the email. Make the MFA lockout
  progressive (backoff) instead of a hard 15-minute block, and email the user on lockout once mail exists.

### 17. Legacy unsealed fallback
- **Where:** `server/src/crypto/seal.ts:47-48`.
- **Fix:** Add a one-time migration or scheduled job that reseals every legacy blob, then remove the no-AAD fallback in
  a later release.

## P3: product and AI-readiness (val.town parity)

Spec and size these before building. Suggested order:

18. **OpenAPI 3.1** generated from the route table (or hand-written next to api.md), served at `/api/openapi.json`.
    Extend `server/test/contract.test.ts` to check request and response shapes, not only that routes exist.
19. **MCP server** (`mcp/` package, stdio + streamable HTTP) wrapping bearer tokens (item 8). Tools: apps list/create,
    files get/put, deploy/promote, env/secrets set, logs tail, invoke.
20. **Per-app token scope:** add an `apps` list next to `projects`/`envs` in `server/src/keys/keys.ts` (`parseTokenReq`).
21. **Idempotency-Key** on `POST` create app, rebuild and create token (store keys in `std:kv` with a 24 h TTL).
22. **`llms-full.txt`** served by the console: the API reference plus the `std:*` type definitions
    (`web/src/lib/std-types/`). Publish the types as an npm package for local editors and agents.
23. **In-editor AI:** an "Explain build failure" action and a "generate from prompt" option at app creation, behind an
    admin setting for the provider and API key (sealed like the OAuth secrets).
24. **Developer loop:** open the code page right after create (the docs already claim this, `apps.md:18`); an inline
    run panel (method, path, body → response and logs); logs docked beside the editor.
25. **Platform features:** fork an app, imports between apps, user-facing SQLite/blob storage via `std:sql`/`std:kv`,
    email triggers, a public explore page for `access: public` apps.
26. **Ops docs:** a restore procedure, metrics and alerting guidance, and an upgrade/downgrade path in
    `docs/admin/operations.md`. Update the `/s/.../tls-ask` references there for the subdomain move.
